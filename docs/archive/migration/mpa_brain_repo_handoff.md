## Substrate-side findings closed by this session

(All in [`mpa_brain_sweep_findings.md`](mpa_brain_sweep_findings.md);
this is the TL;DR for the new-repo session.)

- **ẋ choice for production:** `position-relative` (= $x(t) - x(t_{\text{snap}})$).
  Encodes the substrate's regime structure as a tight plateau in the
  broad-τ × late-dt corner of the (τ, dt) plane, with scenario-
  separable plateau values. Velocity ẋ also encodes the same physics
  but at small dt only and without a tight plateau; kept as a research-
  move alternative, not the prescriptive entry.
- **Production budget:** t_w = 500, t_obs = 10000, n_real = 256,
  τ_windows = geomspace(3, 1000, 11) (or the original 6-point grid
  {3, 10, 30, 100, 300, 1000} — both work; finer grid resolves the
  plateau onset around τ ≈ 50 better). Wall-clock ~5s per run on the
  workstation. Rule-8 budget for position-relative: t_w + t_kw + t_obs
  ≥ 10·τ_max with t_kw = 5·τ_max paid inside phase B before the
  d-snapshot.
- **C(t, t_w) construction:** option 1c from the design memo (in-
  primitive replica averaging). n_real plays the role glass's spatial
  index plays.
- **Snapshot-of-d schedule:** `snapshot_of_d_offset(xdot_kind,
  tau_max)` returns 0 for per-step ẋ (velocity, position-displacement)
  and 5·τ_max for snapshot-relative ẋ (position-relative,
  boundary-cross). For the prescriptive entry (position-relative),
  this means t_kw = 5·τ_max steps of in-phase-B kernel warmup before
  the d-snapshot is taken; substrate snapshot at t_w, d-snapshot at
  t_w + t_kw, paired branches fork at t_w + t_kw.
- **What does NOT work:** the position-relative-d locus does not
  reproduce the single-window V_A FDR atlas (Sweep E). The two
  coordinate spaces (rule 5) read different things; this is recorded
  as F-003, an open framework question, *not* a falsification.
- **Visualizer reads f and ΔC_d, not χ_d.** χ_d in position-relative
  coordinates is mostly noise (Sweep E + Sweep G).

### 3. Lift the sketch into module form

The sketch [`mpa_brain_sketch.py`](mpa_brain_sketch.py) and the
parameterised sweep file [`mpa_brain_sweep.py`](mpa_brain_sweep.py)
are both reorganised into the package:

- `physics_primitives.py` gets: K_BT, DT, D_EFF constants; `_grad`;
  `_sample_dts`; the `compute_xdot` function (with all four kinds
  preserved for research-move use); the `EMA_IN_PHASE_A` mapping;
  `snapshot_of_d_offset`.
- `scenarios.py` gets: A, B anchors; LAM_* constants; R_*_CS / R_*_K
  radii; V0_INTERSECT, V0_MID; U_committed, U_suspended, U_conflict,
  U_reset; V_A_obs; FDR_H_MAG; SCENARIOS dict.
- `measurements.py` gets: `multi_window_fdr_iter` — the event-yielding
  form (not the run-once form). Default `xdot_kind='position-relative'`.
  Yields the v8 streaming events (init, phase_a, snapshot, phase_b,
  sample, complete) per the design memo's "Streaming-primitive event
  shape" table.

The sketch's `multi_window_fdr_iter` already has the right event
shape but uses `xdot_kind='velocity'` implicitly — port the
event-yielding form from the sketch and add `xdot_kind` parameter
defaulting to `'position-relative'`. The kernel-warmup machinery from
`mpa_brain_sweep.py` (`run_one`) needs to be added to the streaming
form: phase_a events during [0, t_w), phase_b events during
[t_w, t_w + t_kw + t_obs), snapshot event at t_w + t_kw, sample events
during [t_w + t_kw, t_w + t_kw + t_obs).

`enrich_sample(sample, T)` follows glass's pattern (in-place mutation
adding `denom`, `R`, `regime`, `Z`, `envelope` fields). Reuse the
glass implementation as the template; thermodynamic temperature
K_BT = 1.0 is a substrate constant.
